# FIELDNOTES · Map First 产品标准与验收（2026-10-18）

> 核心定义：FIELDNOTES 不是给照片叠地图花边，而是把**真实拍摄地点的道路、水系、建筑肌理**与照片融合，做成高质量旅行摄影作品。真实精细地图优先；模板数量、炫酷文案与无地图的花哨排版不得替代地理质量。用户无精细地图时依然能免费、离线生成基本作品，绝不伪造地理数据。

## 一、先修最重要的两处技术问题

### 1. 现有建筑图层没有进入画面
- 当前已使用的 OpenFreeMap / OpenMapTiles PBF **标准有 `building` 图层，现有三份 Z13 离线包也确实含有该图层**。无需为了获取“第一版建筑数据”立刻重新采集全球地图。
- 但当前 `preview/v39/v38-map-core.js` 只解码 `water`、`waterway`、`transportation`、`transportation_name`、`place`、`park`、`landcover`；并不输出/绘制 `building`，故当前不能宣称具备真实建筑肌理。
- 对现有 PBF 以只读方式审计：上海黄浦 9 张 Z13 瓦片，`transportation=6841`、`water=244`、`waterway=92`、`building=9` 条 *vector feature*；陵水为 `346/32/53/4`；西安雁塔为 `3748/115/14/9`。注意 **building feature 是 MVT 要素数，不等于独立建筑栋数**；低缩放级别可能已经概化或合并建筑。
- 首先扩展现有 PBF 解码器，读取真实 Polygon/MultiPolygon 建筑轮廓，按面积/密度/主次等级上色与适度采样；不可画假楼、假街道。建筑细节仍不足时，再评估合法获取小范围 Z14/Z15 建筑包的成本与许可。

### 2. 已下载地图与生成请求的缩放级别不一致
- 当前三个局部离线包都是 **Z13**；而 `FIELDNOTES_STREETS.streets` 对省级请求 Z8、市级 Z12、区县 Z13、真实 GPS Z14。
- 下载/覆盖提示以 Z13 判断，实际生成按不同 Z 请求，可能出现“提示已下载，但画面缺失精细地图”。
- 改造为**覆盖、实际 Z、已缓存资源和绘制质量完全一致**的决策器：只在真正具备所需数据时显示“精细地图已就绪”；无相应层级时明确告知且使用最佳已安装真实层级/基础边界，不可放大 Z13 假装高清 Z14。
- 只预装/按需下载合法可分发的小范围，不把整国建筑/道路包塞进家人手机。

## 二、最终三步交互

| 步骤 | 用户看到的界面 | 后台行为 |
|---|---|---|
| **01 拍照/上传** | 相机 / 相册，原图预览 | 本地处理，读取已授权 EXIF/GPS；照片不上传、人物不重绘 |
| **02 拍摄地点** | 输入/选择地点，自动显示“地图质量”及可选下载 | 真正匹配行政代码、GPS、覆盖瓦片、实际 Z、道路水道建筑图层；已安装立即继续、可增强则明确包大小及局部范围、无增强则可直接继续 |
| **03 一键作品墙** | 默认六张主推作品，下一组六张，再点回第一组；点选后高清导出 | 依据实际地理要素自适应选型；轻量六图预览缓存，导出时按原分辨率绘制 |

第二步用户级文案示例：

- **已准备好：** “✓ 当前地点的精细街道地图已就绪，可直接生成。”
- **能增强：** “找到黄浦区**中心局部**精细地图（道路/水系/建筑，以实测包含的图层为准），约 X MB。下载后可获得更丰富的地理细节。”按钮“下载精细地图 / 使用基础地图继续”。
- **局部覆盖：** “这份包只覆盖附近部分街区，画面会保留实际能获得的地图细节。”
- **没包或断网：** “可以使用真实行政轮廓继续生成，暂时无法显示该地精细街道/建筑。”
- **没有真实 GPS：** 坐标明确标注“区域中心 APPROX.”，不把城市名推断成拍摄点 GPS。

下载/删除必须只影响相应地区的 Cache Storage；卸载说明明确“删除桌面图标 ≠ 必然清空浏览器缓存”，并且绝不清除保存到相册的照片。

## 三、12 款不再平权：数据驱动的 6+6

**首组六款：按数据质量挑选，而非每地硬凑同一套。**

| 推荐方向 | 要求的数据 | 视觉核心 |
|---|---|---|
| 01 城市路网 | 足够真实道路及级别 | 大小道路层级、细腻街网纹理 |
| 02 水系地理 | 实际河网/海岸/湖泊 | 水面与河道层级，不能虚构河流 |
| 03 建筑肌理 | 可识别真实建筑面 | 建筑轮廓、疏密与街区块面 |
| 04 综合地理 | 道路＋水/建筑适合组合 | 地理纹理与照片互融 |
| 05 夜间地图 | 真实路网，建筑有则补充 | 灯光式高对比路网，非单纯换黑色 |
| 06 克制的地图档案 | 至少真实地理边界 | 留白、小地图/坐标章，保护照片主体 |

没有相应图层、密度过低或瓦片未覆盖时：自动降低该方案的推荐优先级，替换为适合现有数据的真实地图/摄影作品样式，不宣称有建筑/水系。允许六张主推因照片构图和当地地图质量而不同。

**第二组六款：** 画册、纪实、明信片、档案、信息侧栏等明显不同的摄影编辑结构。现有 V3.7/V3.8 Canvas 版式优先改良，不另起 React/Fabric/MapLibre 全套工程。主推作品审美不合格时，不用第二组模板数凑业绩。

**共同要求：** 道路细节不能遮挡人脸/人物/动物/地标主体；优先使用现有手动保护框，自动保护必须先验模型兼容、隐私与性能。两组六张预览可循环切换，第一组回访不得重新生成；选中才走原分辨率 PNG 导出。

## 四、实施顺序（一次验收一个模块）

1. **P0 地图正确性（先做）**：Z12/Z13/Z14 与覆盖匹配；实际绘制与“已就绪”一致，回归陵水/黄浦/雁塔的区县/市级/GPS/未下载/离线场景。
2. **P0 建筑解码＋密度判断**：复用 `@mapbox/vector-tile` + `pbf`，证明建筑来自现有真实矢量数据，实际展示；如密度不足才增补按需 Z14/Z15。
3. **P1 地图美学与 6 主推**：拿酒店人像、白鲸水域和城市实景等**经用户授权的真实原片在受控环境**做 A/B，记录版式/主体遮挡/文字清晰度/道路建筑层级；不得把仿真彩块截图当审美通过。
4. **P1 国内双端交付**：无域名/无 VPN 的中国普通网络首次访问和离线重启、Android 微信真实保存相册、iPhone Safari/PWA 保存、按地区删除缓存。与网站域名/发布渠道现实约束分开验收，不得提前宣布成功。

## 五、量化验收

- 数据：建筑/道路/水域仅在真实矢量图层存在且实际覆盖时标注可用；禁止假 GPS 和假路网。
- 缩放：有包时绘制的真实图层与缓存瓦片的 Z、x、y 严格一致；不允许“已下载但出图降成轮廓而不提示”。
- 体验：地图包按需独立下载/删除、无包也出图、6+6 切换恢复缓存；导出保持原始像素尺寸（受设备内存边界时提示），无照片外传。
- 质量：实拍不同人像/城市/海景的主推 6 款必须做人工盲选 A/B；肉眼无区分、主体被遮、文字拥挤的款式不能作为推荐。
- 性能：手机六张缩略预览暖启动中位目标不超过 2 秒，**必须以国产中端 Android 与 iPhone 真机记录为准**；CI 的 100–900ms 只作为参考，不替代真机。
- 交付：继续使用 GitHub PR、隔离环境及 CI；P0 未通过不合并风格扩展 PR；现有 V3.9、V3.8-P1 和正式 V3.6 页面不被破坏；尽量不使用 Remote Desktop Commander。
